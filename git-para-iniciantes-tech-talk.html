Git para iniciantes

Versionamento de código sem medo, para quem cria com IA

Tech Talk · Orla
Antes de tudo

O que é Git?

Um programa que guarda todas as versões do seu projeto e deixa você voltar no tempo quando quiser.

Controle de versão, em uma frase.

Por que isso importa

Você já cria software. Falta a rede de segurança.

Você usa IA

Cursor, Claude, Lovable, v0… o código nasce rápido.

Muda o tempo todo

Cada ideia nova mexe em vários arquivos de uma vez.

Quebra fácil

Uma alteração errada e o que funcionava some.

Vai pro ar

Vercel, Netlify e afins publicam direto do seu repositório.

O problema

Sem versionamento, você vira refém do "final_v2_FINAL".

A vida sem Git, na prática:

  • projeto-final.zip, projeto-final-2.zip, projeto-final-AGORA.zip
  • "funcionava ontem" e ninguém sabe o que mudou
  • apagou algo sem querer e não tem como voltar
  • dois computadores, duas versões diferentes
  • colaborar virou trocar arquivo no WhatsApp
Conceito

Git é uma máquina do tempo para o seu projeto.

Controle de versão

Cada vez que você salva um marco, o Git guarda uma foto completa do projeto. Dá pra voltar a qualquer ponto, comparar versões e nunca mais perder trabalho. Tudo isso no seu computador, de graça e funcionando offline.

Pergunta-guiaO que mudou, quando, e como volto se der errado?
A diferença que confunde todo mundo

Git ≠ GitHub

Git · a ferramenta

Roda no seu computador. Guarda o histórico do projeto. Funciona offline. Grátis e de código aberto.

GitHub · o lugar na nuvem

Guarda seu repositório online. Faz backup automático. Deixa várias pessoas (e IAs) colaborarem no mesmo código.

Existem outras opções: GitHub é só um dos lugares. Também há GitLab e Bitbucket. E o Git nem é a única ferramenta de versão (existem Mercurial, SVN). Mas Git + GitHub é o padrão do mercado hoje.

Quatro palavras e você já se vira.

Uma linha do tempo paralela pra testar sem medo.

Remote

A cópia que vive na nuvem (no GitHub).

O fluxo do dia a dia

Quase tudo é este ciclo.

Repete o tempo todo, sem mistério.

1 · Mudarvocê (ou a IA) edita os arquivos
2 · Addescolhe o que entra no próximo save
3 · Commitsalva com uma mensagem do que mudou
4 · Pushenvia tudo para o GitHub
Conceito · Commit

Commit é um ponto de salvamento.

Como o save de um videogame

Cada commit guarda uma foto do projeto e uma mensagem curta. É a sua trilha de migalhas: quando algo quebra, você volta pro último commit que funcionava.

git add . # marca o que vai no save git commit -m "adiciona tela de login" # salva com mensagem
DicaMensagem boa = você do futuro agradece.
Conceito · Branch

Branch é um universo paralelo.

Testar sem arriscar o que já funciona

Quer experimentar uma ideia maluca? Cria uma branch e mexe à vontade. Deu certo, você junta (merge) no principal. Deu errado, joga fora. O original continua intacto.

git checkout -b nova-ideia # cria e entra na branch # ... testa à vontade ... git merge nova-ideia # junta se gostou
Conceito · Nuvem

Push manda, Pull traz.

Push ↑

Envia seus commits do computador para o GitHub.

Pull ↓

Traz para o seu computador o que mudou no GitHub.

É assim que tudo se conecta: trocar de máquina, fazer backup e colaborar. Todo mundo sincroniza pelo mesmo repositório.
Cola

Os comandos que resolvem 90% dos dias.

git init # começa a versionar uma pasta git status # o que mudou? git add . # marca tudo pro próximo commit git commit -m "..." # salva com mensagem git push # envia pro GitHub git pull # traz do GitHub git log # vê o histórico
Sem terminal também vale: muita gente faz tudo isso por botões (VS Code, GitHub Desktop), sem digitar nada.

GitHub · Colaboração

Pull Request: "olha o que mudei, pode entrar?"

Você faz suas mudanças numa branch e abre um Pull Request (PR). Os outros veem exatamente o que mudou linha a linha, comentam, e só então junta no projeto principal.

É a porta de revisão, e também onde os agentes de IA de code-review entram pra te ajudar a achar problemas antes de subir.
Para quem cria com IA

Git é a sua rede de segurança com a IA.

Commit antes do pedido grande

se a IA bagunçar, o Git volta tudo num clique.

A IA deixa de assustar

você sempre tem o "estado que funcionava" salvo.

As ferramentas já falam Git

Cursor, Claude Code e Copilot commitam e criam branches pra você.

Deploy automático

fez push, o site se atualiza sozinho.

Sem medo

Os perrengues parecem piores do que são.

O medo

"Vou quebrar tudo" "Conflito de merge dá pânico" "São comandos demais" "Isso é só pra dev raiz"

A realidade

O Git guarda tudo: sempre dá pra voltar Conflito = vocês mexeram na mesma linha; você decide qual fica 6 comandos (ou só botões) resolvem o dia Hoje é pra qualquer um que cria

Ferramentas

Você não precisa do terminal.

Várias formas de usar o mesmo Git. Escolha a que te deixa confortável:

VS Code · Source Control GitHub Desktop GitKraken Sourcetree Terminal
Lembrete: Git é a base, GitHub é um host. Hosts alternativos: GitLab, Bitbucket. O importante é começar. A ferramenta visual é só detalhe.
Boas práticas

Hábitos que salvam.

Commit pequeno e frequente

fácil de entender e de reverter.

Mensagem clara

"corrige bug do botão", não "asdf".

Push todo dia

backup automático sem esforço.

Uma branch por tarefa

uma ideia, uma linha do tempo.

Nunca suba senhas

use .gitignore e variáveis de ambiente.

Leia o diff

veja o que muda antes de salvar.
